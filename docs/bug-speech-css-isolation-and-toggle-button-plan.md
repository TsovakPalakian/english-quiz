# План устранения коллизий изоляции стилей и селекторов формы речевого модуля

## 1. Анализ проблемы и первопричины

В ходе выполнения полного набора тестов было выявлено 2 ключевых фактора падения тестов:

1. **Коллизия глобального селектора `.saas-card`**:
   - В добавленных стилях речевого модуля селектор `.saas-card` был определен глобально на одном уровне с `.speech-task-card` с правилом `display: flex;`.
   - В разметке категорий грамматики модальное окно `<dialog id="grammarNewRuleDialog" class="saas-card">` использует класс `saas-card`.
   - Глобальное правило `display: flex;` переопределило браузерное поведение закрытого диалога `dialog:not([open]) { display: none; }`, в результате чего модальное окно отображалось поверх основного содержимого страницы и перехватывало события указателя (`subtree intercepts pointer events`) в более чем 20 тестах.

2. **Нарушение строгого режима Playwright в тесте `test-learning-workbench-ui`**:
   - Тест выполняет поиск кнопки отправки формы через `locator('[data-speech-form=task] button')`.
   - Добавленный интерактивный переключатель опции языкового анализа был реализован через тег `<button type="button" data-speech-toggle="languageReview">`.
   - Наличие двух тегов `<button>` внутри формы вызвало исключение Playwright `strict mode violation: locator('[data-speech-form=task] button') resolved to 2 elements`.

## 4. Спецификация изменений

1. В стилях:
   - Заменить глобальные правила `.saas-card`, `.saas-btn-primary`, `.badge`, `.btn-primary` на `.speech-panel .saas-card`, `.speech-panel .saas-btn-primary` и т.д.
   - Добавить явное правило `dialog:not([open]) { display: none !important; }`.
2. В компоненте интерфейса речи:
   - Отрендерить переключатель как `<div role="button" tabindex="0" class="speech-toggle-btn saas-toggle-btn" data-speech-toggle="languageReview" aria-pressed="true" data-checked="true">...</div>`.
   - В обработчике событий поддержать переключение по клику и по нажатию клавиш Space / Enter.
