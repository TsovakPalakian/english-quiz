### Резервная копия локальных медиа и отдельное восстановление

`scripts/turso-media-backup.mjs` включён в `turso-backup.mjs --create`.
Из зафиксированного snapshot берутся все локальные ссылки library_items и
lesson_blocks, включая soft-deleted записи. Копируются только эти immutable
объекты: отсутствие/подмена файла или другая owner/block привязка прерывает
создание успешной копии. Турso содержит только метаданные; файлы находятся в
`local-media/`, контрольные суммы и точные references — в `local-media.json`.
Общий manifest связывает хеш снимка и media manifest. Завершённая существующая
копия не дополняется и не перезаписывается.

Ограничения одной локальной копии: 1 000 объектов, суммарно 512 MiB, каждый
файл до 10 MiB. Приватные каталоги/файлы 700/600; symlink и произвольные пути
не принимаются. Повреждение, пропуски, лишние/дублированные ссылки и неверные
checksums отклоняются при verify до восстановления.

`--restore-local-media <backup>` проверяет общую копию и создаёт **новый**
приватный media-каталог. Runtime-журнал, работающая БД, исходные файлы и R2
не изменяются. Это отдельная проверка/артефакт, не автоматический rollback сайта.
Оригинальные orphan-объекты также не удаляются и не выдаются за активные ссылки.

### Файлы урока: изолированный локальный путь, без production PUT/DELETE

Ответы учащихся и соседние блоки не перезаписываются; старый ответ к изменённой

прежние объекты не удаляются; отключённая ссылка перестаёт разрешаться через API.

это изменение без удаления самого файла или production R2 DELETE.

перенос ключа из песни или другого блока отклоняется. Старые повторно
использованные legacy file IDs сохраняют прежний путь чтения R2.

Точный ID неопределённой загрузки сохраняется без бинарных данных. Повтор после
перезагрузки восстанавливает исходную версию операции для того же account/path,
хеша/имени/MIME файла, даже если сервер уже показывает подтверждённую новую

### Локальная загрузка аудио: код готов, живая приёмка ещё не выполнена

`src/turso-song-media.mjs`, `scripts/turso-local-media.mjs` и основной staging
сервер поддерживают POST `/api/library/:id/media` для собственной сохранённой
песни. В UI добавляется отдельная форма аудио, только на 127.0.0.1. MP3/WAV/OGG
до 10 MiB проверяются по MIME и начальной сигнатуре (не полный декодер). Бинарный
body передаётся отдельно; в Turso обновляются только media_key, fileName/fileType
и revision, без binary/base64 и без записи всего массива песен.

Файлы и предзаписанный журнал размещаются в отдельном mode-700 каталоге
`/private/tmp/english-quiz-stage-media-*`, файлы mode 600. Адреса неизменяемые,
по SHA-256; исходное аудио при замене не удаляется. CAS и квитанция защищают от
потерянного ответа и повторного увеличения версии. Неопределённый исход записи
не запускает удаление: возможные orphan-файлы сохраняются для отдельного review.
При повторе после перезагрузки UI требует выбрать тот же файл; в localStorage
сохраняются только параметры/хеш/ID операции, не аудио. Private GET/HEAD/Range
сверяют checksum; доступ проходит через текущий профиль и связь с песней.

Runtime-журнал `rollback/turso-local-media.json` хранит путь, чтобы последующие
запуски использовали тот же каталог. Это только локальная тестовая среда:
системная очистка tmp может удалить файлы; полноценное удалённое размещение и
бинарная резервная копия ещё обязательны. Копия Turso сама по себе эти новые
бинарные файлы не содержит. Worker отклоняет stage-local ссылки без fallback
в production R2; удалённая загрузка не включена.

47 автономных тестов прошли, включая HTTP на временном localhost, SQLite,
owner/CSRF/CAS, повтор после перезагрузки, замену, HEAD/Range и checksum.
