# План исправления динамического наименования провайдера в согласии Speech и снятия предвыбора чекбокса

> [!WARNING]
> <span style="color: red; font-weight: bold;">WARNING</span>
> **ПРЕДУПРЕЖДЕНИЕ О НЕПРИКОСНОВЕННОСТИ СМЕЖНОГО ФУНКЦИОНАЛА:**
> Выполняемая задача строго и изолированно затрагивает исключительно текстовый шаблон чекбокса согласия на анализ аудиозаписи в форме анализа речевой практики:
> 1. Восстановление исходной строки-заполнителя в разметке чекбокса согласия для корректной работы динамической подстановки имени активного провайдера распознавания речи (включая сценарий с внешним сервисом).
> 2. Удаление атрибута автоматического предвыбора с чекбокса согласия для обеспечения требования явного волеизъявления пользователя перед отправкой на анализ.
> 3. Сохранение полной стилизации блока согласия и карточки настроек приватности без изменения смежных стилей и логики.
>
> Строго запрещено затрагивать, модифицировать или нарушать смежные модули:
> - Алгоритмы захвата аудиопотока и кодирования PCM16.
> - Аутентификацию, сессионные куки и профили учетных записей.
> - Настройки провайдеров и серверные роуты в рабочей панели.
> - Базу данных SQLite, а также независимые разделы обучающего портала.

## 2. Описание проблемы и анализ причин сбоя

1. **Несовпадение строки подстановки провайдера**:
   - Вспомогательный метод динамической сборки интерфейса выполняет замену базовой текстовой строки `Send this recording to the selected synthetic local analyzer` на актуальное наименование сконфигурированного движка распознавания (`state.analyzerLabel`).
   - При предыдущей стилизации под макет текст внутри тега подписи чекбокса был жестко заменен статическим текстом, из-за чего механизм замены не находил целевую строку и оставлял статический текст независимо от выбранного провайдера.
2. **Атрибут предвыбора чекбокса**:
   - В разметку чекбокса был добавлен атрибут предвыбора, что нарушает контракт безопасности и проверки на стороне интеграционных тестов, требующих обязательного начального состояния без установленной отметки.

## 3. Поэтапный план реализации

* 🟩 **Этап 1: Восстановление базового шаблона подписи согласия** (Возврат строки-заполнителя в разметку для обеспечения работы динамической подстановки сконфигурированного провайдера).
* 🟩 **Этап 2: Снятие атрибута автоматического предвыбора чекбокса** (Удаление атрибута с элемента выбора для обеспечения явного подтверждения пользователем).
* 🟩 **Этап 3: Сборка клиентских ресурсов и верификация тестами** (Сборка бандла предпросмотра, выполнение целевого сценария проверки интеграции провайдера и тестов визуального оформления интерфейса).

---

## 4. Чек-лист проверки

- 🟩 Базовая строка согласия в разметке совпадает с целевой строкой метода замены.
- 🟩 При выборе провайдера в подписи чекбокса отображается его наименование.
- 🟩 Чекбокс согласия по умолчанию не отмечен.
- 🟩 Тестовый сценарий проверки интеграции провайдера завершается успешно.
- 🟩 Визуальный тест оформления панели речевой практики завершается успешно.
