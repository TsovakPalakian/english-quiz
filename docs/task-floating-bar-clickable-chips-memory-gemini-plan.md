# План реализации плавающей плашки Start, кликабельных чипов навигации, настройки пар Memory и интеграции Gemini с изображениями

> [!WARNING]
> <span style="color: red; font-weight: bold;">WARNING</span>
> **ПРЕДУПРЕЖДЕНИЕ О ЗАТРАГИВАНИИ СМЕЖНОГО ФУНКЦИОНАЛА И НЕПРИКОСНОВЕННОСТИ СИСТЕМЫ:**
> Текущая задача строго изолирована и касается исключительно:
> 1. Стилизации нижней плашки квиза `.dq-foot` как плавающей (floating / sticky) с фиксацией в нижней части окна просмотра при прокрутке длинного списка режимов и групп Custom mix.
> 2. Добавления интерактивности чипам выбранных типов в плашке готовности: по клику на чип выполняется плавная прокрутка к кнопке соответствующего типа в блоке режимов или Custom mix с кратковременной акцентной подсветкой.
> 3. Добавления элемента управления количеством пар для режима Memory (селектор / степпер от 2 до 8 пар) в карточке или настройках типа.
> 4. Интеграции генерации пар Memory через Gemini API с формированием смысловых пар (слово + перевод / дефиниция) и поддержкой графических карточек с изображениями.
> Запрещено затрагивать, модифицировать или нарушать смежный функционал:
> - Алгоритмы интервального повторения FSRS и Anki cards.
> - Систему навигации хлебных крошек и шапку урока.
> - Режимы Quick review, Write it, Listen, Play.
> - Классический интерфейс настроек квиза `#dayStudyClassic` и экран урока `#material`.

## 1. Точная формулировка проблемы (Problem Statement)

1. **Плавающая плашка готовности (Скриншот 1 в запросе)**:
   - В текущей разметке плашка `.dq-foot` находится в самом низу экрана настроек квиза под блоками Cards, Review, Mode и Custom mix. При раскрытии всех 18 типов Custom mix страница становится длинной, и для старта квиза пользователю приходится прокручивать экран до самого конца.
   - Требуется сделать плашку плавающей (`position: sticky; bottom: 16px;`), чтобы она всегда оставалась видимой и доступной в нижней части экрана поверх прокручиваемого содержимого.

2. **Кликабельные чипы навигации к типам упражнений (Скриншот 2 в запросе)**:
   - Чипы `.dq-chip` в блоке готовности выводятся как статические текстовые элементы.
   - Требуется сделать чипы интерактивными кнопками (`cursor: pointer`), клик по которым выполняет плавную прокрутку страницы (`scrollIntoView({ behavior: 'smooth', block: 'center' })`) непосредственно к карточке или кнопке соответствующего типа упражнения с кратковременным визуальным фокусом.

3. **Настройка количества пар для режима Memory**:
   - В текущей реализации режима Memory размер сета жестко зафиксирован (по умолчанию 4 пары = 8 карт). В блоке Custom mix отсутствует возможность изменить число пар.
   - Требуется добавить элемент выбора количества пар (степпер от 2 до 50 пар, то есть до 100 карточек на поле) для точной регулировки сложности игры.

4. **Генерация упражнений Memory и графических карточек через Gemini**:
   - На приложенном Скриншоте 3 карточки Memory открываются с точками `·` в рубашке, а при нехватке пар в уроке упражнение не может сформировать смысловой набор.
   - Через Gemini API в проект интегрируется генератор пар для Memory: модель формирует сбалансированные пары (слово / перевод, слово / определение, слово / контекст), а также связывает карточки с иллюстрациями и графическими миниатюрами.

## 2. Границы области изменений и инварианты (Scope Boundaries & Invariants)

- **Затрагиваемые файлы**:
  - `site/preview.css`: стили плавающей плашки `.dq-foot` (`position: sticky; bottom: 16px; z-index: 35; backdrop-filter: blur(10px); box-shadow: ...;`), стили интерактивных чипов `.dq-chip`, стили карточек Memory с изображениями.
  - `site/preview.html`: добавление элемента настройки числа пар для Memory в секцию Games.
  - `client/03g-core.js`: обработчик клика по чипам с прокруткой к целевому типу, чтение выбранного числа пар Memory, рендеринг карточек Memory с поддержкой картинок (`face.image`).
  - `client/52-lessons.js` / модуль генерации: вызов Gemini для формирования пар Memory и графических карточек.
  - Тесты в `test/`: верификация плавающей плашки, кликабельности чипов, настройки пар Memory и генерации.

- **Инварианты**:
  - Использование исключительно переменных CSS (`--bg`, `--card`, `--ink`, `--mute`, `--line`, `--acc`, `--acc-s`, `--on-acc`).
  - Сохранение полной работоспособности всех режимов квиза.
  - Корректная работа Memory при наличии как только текста, так и текста с изображениями.

- 🟩 **Этап 8**: Пересборка клиентских ассетов (`npm run build:preview` и сборщик продакшена).
