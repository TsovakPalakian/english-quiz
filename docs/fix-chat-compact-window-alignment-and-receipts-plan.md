### Анализ дефекта и изолированное решение

1. **Идентификация авторства сообщений в компактном окне:**
   - В функции `syncMiniTimeline` сопоставление `own` опиралось на строгое равенство `sId && myId ? sId === myId : m.classList.contains('is-own')`.
   - Если идентификатор в `sId` (`m.dataset.senderId`) расходился по формату с `myId` (`myAccountId()`), условие вычислялось как `false`, блокируя проверку `m.classList.contains('is-own')`.
   - Решение: автономно внутри `syncMiniTimeline` проверять принадлежность реплики текущему пользователю по комплексному набору идентификаторов сессии (`user.id`, `user.login`, `user.name`, `profile.id`, `profile.name`, `account`, а также класс `is-own` и статус `pending`), гарантируя, что исходящие реплики получают контейнер `.chat-mini-msg-row.own`.

2. **Отображение галочек статуса доставки и прочтения:**
   - Для собственных сообщений формируется разметка `.chat-mini-receipt` с прямым инлайн-рендерингом SVG-галочек Lucide (`check` для отправленных, `check-check` для доставленных и прочитанных).
   - Это исключает зависимость от внешнего прогона `lucide.createIcons` и обеспечивает мгновенное появление галочек рядом со временем.

### Контрольный список реализации

- 🟩 **Этап 1: Автономная идентификация собственных сообщений в компактном окне** — расширение валидации автора в `syncMiniTimeline` без изменения публичных интерфейсов и глобальных состояний.
- 🟩 **Этап 2: Инлайн-отрисовка галочек статуса доставки и прочтения** — вывод индикаторов `.chat-mini-receipt` рядом со временем для всех реплик пользователя.
- 🟩 **Этап 3: Сборка клиентских скриптов и визуальная проверка** — генерация бандла через `npm run build:preview`, сверка с утвержденными скриншотами.
- 🟩 **Этап 4: Таргетированные автоматические тесты** — создание и прогон тестового сценария проверки расположения реплик и наличия галочек.
