# Основной интерфейс: изолированный локальный стенд

Адрес: `http://127.0.0.1:8789`. Отдельный порт от демонстрационного стенда 8788.

Обновление 2026-10-04: новые личные карточки вручную, точечные тексты/песни,
read-only медиа, новая личная activity-статистика, отдельный отключённый Worker
и проверенная резервная копия добавлены. Текущий статус/блокеры этапов 2–6:
[turso-batch-progress.md](turso-batch-progress.md). Исторические проверки ниже
не заменяют ещё не выполненную полную браузерную приёмку нового пакета.

```bash
node scripts/run-turso-main.mjs
node --test scripts/test-turso-stage.mjs scripts/test-turso-main.mjs scripts/test-turso-personal.mjs
```

Это локальная интеграция, не опубликованный staging Worker и не production.
Рабочие `preview.js`, `preview.html`, `src/worker.js`, `wrangler.toml` не
изменены: hooks вставляются только в копию JS, которую отдаёт тестовый сервер.
При несовпадении точного якоря сервер отказывает, а не правит произвольный код.
Для обновления интерфейса после правок перезагрузить страницу. Остановить Ctrl+C.

## Настоящий вход

В форме Account → Log in вводятся **существующие** логин и пароль, не в чат.
Пароль проверяется локально тем же PBKDF2-SHA256/100000, что в рабочем Worker.
Plaintext-пароль не отправляется Cloudflare/Turso и не сохраняется. Соли/хеши
аккаунтов не выгружаются в файлы, не копируются в Turso и не выводятся в логи.

Каждый вход выполняет один фиксированный SELECT из production D1 `users`.
Каждый защищённый HTTP-запрос выполняет один SELECT живого аккаунта, а не
запрос на каждую карточку/SQL-подзапрос. Проверяются active/revoked, роль и
отпечаток актуального password_hash. Дополнительно читается R2 `gone/<id>`;
privacy-маркер отзыва не обходится. Роли из JSON/заголовков не принимаются.
Ни schema-init, ни SELECT user_state, ни D1-записей, ни R2-записей здесь нет.

Жёсткий лимит процесса: **50 auth-SELECT в час**. Нет polling, автоматических
сетевых повторов, JWT-only fallback или кеша живых ролей. При лимите/ошибке
аккаунты не проверяются по устаревшему снимку: HTTP 503, запись запрещена.
Лимит — защита локального стенда, не глобальный лимит/метрика всей D1.
Тестовые сессии — отдельные случайные HttpOnly/SameSite=Strict cookies на час,
только в памяти процесса. Они не являются production sid. Logout удаляет
локальную сессию, не разлогинивает рабочий сайт. Перезапуск сервера требует
повторного входа. Не запускать этот management-API-backed сервер публично.

Используется существующая авторизация Wrangler, либо уже заданный
`CLOUDFLARE_API_TOKEN`; браузеру platform-token не передаётся. При истечении
Wrangler-сессии выполнить установленной CLI `wrangler whoami` для штатного
refresh, при необходимости `wrangler login`. Scope не расширять. Production
secret сессий не меняется и не используется для тестовых cookies.

Новые после снимка аккаунты без `profile_members` не получают профиль
автоматически: чтение учебного состояния даёт 409. Добавление аккаунта в
тестовую миграцию — отдельная контролируемая операция.

## Что подключено

- Основной внешний вид/навигация, статические банки из `catalog_documents` и
  актуальных общих определений Turso, а не старых JS-копий. Tombstone исключается.
- Уроки/блоки с published/hidden/личными правилами видимости. Ответы выдаются
  только профилю текущего аккаунта; quarantined migration_issues не читаются.
- Личные карточки, тексты/песни-метаданные, настройки и существующий прогресс
  читаются только из своего профиля. Общая пара использует прежний общий профиль.
- Save карточки на этом этапе редактирует **только перевод**. Остальные поля
  не показываются как якобы сохраняемые. Карточка выбирается по stageId; при
  неоднозначном legacy-сопоставлении запись отказывается без угадывания ID.
- Добавление квиза создаёт видимый **черновик**, который пишется после **Done**.
  Done отправляет один POST/PATCH; крестик — DELETE одного постоянного ID.
  Поддерживаются имена 17 типов основного интерфейса. Движок игр не переписан.
- Save/delete подтверждаются после ответа Turso. expectedRevision защищает
  от потери конкурентного изменения; неподтверждённый mutationId сохраняется
  для ручного повтора. При конфликте нужен новый просмотр серверного состояния.
- Длинные импортированные ID квизов не обрезаются до legacy-лимита 64 символа.
  Save/Done сохраняет revision открытой формы даже после фонового обновления
  регистра данных, чтобы не перезаписать более новое изменение другого редактора.
- Старые localStorage/IndexedDB карточки и песни не восстанавливаются поверх
  серверного состояния; orphan-квизы и старые уроки не отправляются обратно.

## Личные ссылки на карточки

- `POST /api/me/cards`: cardId, place, expectedCardRevision, expectedRevision,
  mutationId. Сохраняется одна ссылка в `profile_cards`, без копирования cards.
  Профиль определяется сервером; USER/teacher/dev могут менять только свой.
- «Добавить слово» в основном UI ищет точное совпадение в **видимых** карточках
  тестовой Turso. Нет совпадения / несколько ID — явный отказ без угадывания.
  Внешний словарь отключён. Новую карточку можно создать вручную через English/
  Russian в собственной форме; POST /api/me/cards/new создаёт private определение
  и ссылку атомарно. Повтор/конфликт версии не создаёт дубликат.
- `DELETE /api/me/cards/:id`: place, expectedRevision, mutationId. Удаляет только
  собственную ссылку, не определение и не прогресс. Для USER показана только
  кнопка удаления, без редактирования общей карточки. Teacher/dev по-прежнему
  редактируют перевод общей карточки; глобальное удаление остаётся в каталоге.
- CAS всего списка хранится в `profile_settings.tursoCardLinks.revision`;
  значение `{}` не является учебной настройкой и исключено из stats. Версия
  не сбрасывается после удаления/повторного добавления. Нет нового DDL.
- UI меняется только после подтверждения; неопределённый результат сохраняет
  тот же payload/mutationId для ручного повтора. Legacy whole-state PUT запрещён.

## Личный прогресс и ответы

- `POST /api/cards/:id/answers`: correct, quizType, expectedRevision, mutationId.
  Сервер считает misses/streak; четыре успеха очищают weak check, но строка с
  revision остаётся. correct для практики сообщает клиент: это не защищённый
  экзамен и не автоматическая отметка всей карточки learned.
- `PATCH /api/cards/:id/progress`: learned/variants. API/bridge готовы; новых
  кнопок управления этими полями в интерфейсе на этом этапе не добавлено.
- `PUT /api/lessons/:lessonId/blocks/:blockId/response`: только текст task или
  выбранные/введённые ответы Choice/exercise. Check вычисляет score/marks по
  определению на сервере. Клиентские answer/correct/marked/score запрещены.
  Общие lesson_blocks/content_json не обновляются.
- Профиль определяется только по profile_members вошедшего аккаунта.
  Чужой profileId/forUserId запрещён, включая учителя/разработчика. Прежняя
  пара аккаунтов продолжает разделять профиль. Видимость, членство и версии
  перепроверяются в транзакции. expectedRevision=0 только для новой строки;
  expectedBlockRevision защищает ответ на изменённое задание.
- Ввод объединяется на 1 секунду, blur/Check отправляет сразу. Очередь сохраняет
  аккаунт, payload, baseline и mutationId до отправки. Ошибка/409 останавливает
  её; «Повторить» использует тот же payload/ID, не новую попытку с новой версией.
  Очередь не переадресуется после смены аккаунта. «Проверить сервер» требует
  подтверждения отмены несохранённых изменений. Выход блокируется, пока они
  не подтверждены или явно отменены.
- Прогресс считается подтверждённым только после ответа; введённый текст пока
  может быть черновиком. Перезагрузка восстанавливает ответы своего профиля.
  Старые picked/typed/marked/correct/score из общего JSON не являются ответами
  ученика. Отдельные события Statistics/экзаменов/время занятий не перенесены.

## Редактирование уроков

- Создание: `POST /api/lessons` с постоянным ID нового урока, metadata и новыми
  blocks. Изменение: `PATCH /api/lessons/:id` с expectedRevision, только изменёнными
  changes/upserts/deletes; order отправляется только при изменении порядка.
  Старый `PUT /api/lessons` со всем списком остаётся запрещённым (501).
- Только актуальные ADMIN/DEVELOPER могут менять определения. CAS урока и
  изменяемых блоков, запись и receipt выполняются атомарно; stale block откатывает
  даже предшествующее изменение заголовка. Повтор использует тот же mutationId.
- Редактор сохраняет локальный черновик, но не делает сетевой autosave при каждом
  символе. Save Draft/Publish подтверждаются только после серверного ответа;
  до ответа элементы редактора временно блокируются. Published/hidden проверяются
  на сервере. Hide пишет только флаг и не сохраняет остальные локальные правки.
- Delete lesson и удаление блока — soft-delete; карточка по cardId, другие уроки,
  доступы и личные ответы физически не удаляются. Ученикам удалённый урок не виден.
- Поддержаны текстовые/структурные блоки: heading, text, link, cards, vocab,
  exercise, quiz, note, dialogue, reading, table, task, divider, phrase, rule.
  Word/wordcard связывается с существующей общей карточкой по ID, без копирования
  или перезаписи её содержимого. Изменение/создание media-блоков пока запрещено;
  существующие неизменённые media сохраняются при правках других блоков/metadata.
- Личные picked/typed/marked/correct/score/response не отправляются как определения.
  Новые ответы хранятся с версией определения. После изменения блока старый
  ответ остаётся в БД, но не накладывается на новое задание; новый ответ может
  записаться с актуальной версией блока и прежней revision собственной строки.
  Импортированные ответы без обёртки отображаются только при revision блока=1.
- Ограничения стенда: до 200 блоков, до 100 items, content блока до 32 тыс.
  символов, общий HTTP body до 64 KiB. Большая операция отказывается целиком.

## Намеренно ещё не включено

Загрузка/замена файлов, новые media-блоки, общая административная статистика/
старая история R2, управление учениками и аккаунтами, dictionary/analyzer,
внешние медиа/embed. Новые карточки/тексты/песни и личные события подключены;
R2/inline-media только read-only. Неперенесённые операции
показывают предупреждение и/или HTTP 501; никакого proxy/fallback в production
для них нет. Перенесены practice weak checks и личные ответы task/Choice/exercise,
не вся игровая аналитика или история экзаменов. Нельзя считать все счётчики
Statistics/Home готовыми. Для обычных занятий пока использовать рабочий сайт;
новый этап остаётся тестовым. Медиа не следует считать готовыми.
