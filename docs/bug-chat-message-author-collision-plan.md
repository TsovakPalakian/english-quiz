## 1. Точная формулировка проблемы и анализ первопричины

- **Проблема**: В личной переписке сообщения собеседника (в частности, сообщение «1234» и предшествующие реплики учителя) отображаются на правой стороне экрана с фоном собственных сообщений (`is-own`) и с аватаром текущего пользователя вместо аватара фактического отправителя.
- **Первопричина (Определение принадлежности `isOwnMessage`)**:
  В функции `isOwnMessage` проверка:
  ```javascript
  if (data?.profile?.name && m?.sender && String(m.sender) === String(data.profile.name)) return true;
  ```
  срабатывала по совпадению имени пользователя, даже если у сообщения указан чужой `senderId`, отличный от `myAccountId()`. В ситуации, когда у собеседника то же отображаемое имя (например, учитель и ученик с общим именем «Tsovak Palakian»), все входящие сообщения помечались как исходящие (`is-own = true`).
  При этом в `production/chat/00-core.js` сохранялся старый код, так как в предыдущем коммите был скорректирован только вспомогательный мини-чат.
- **Отрисовка аватара в `syncDays`**:
  В функции `syncDays` при наличии класса `is-own` идентификатор автора заменялся на `myAccountId()`:
  ```javascript
  const id = own ? ((typeof myAccountId === 'function' ? myAccountId() : '') || message.senderId) : message.senderId;
  ```
  После изоляции `isOwnMessage` входящие сообщения не получают класс `is-own`, благодаря чему `id` строго равен `message.senderId` (идентификатору учителя), и аватар отображается слева с правильным фото и статусом.

## 2. Поэтапный чеклист реализации

- 🟩 **Этап 1: Коррекция логики идентификации авторства `isOwnMessage` в `production/chat/00-core.js`**
  - Восстановление и сохранение инварианта `if (me && String(m?.senderId ?? '') === me) return true;` для соответствия статическим проверкам долговечного чата.
  - Приоритет проверки `senderId`: если `m.senderId` (или `m.sender_id`) передан и не совпадает с `ownIds`, функция гарантированно возвращает `false` без отката к совпадению отображаемых имен.
  - Сохранение отката к имени исключительно для сообщений, где `senderId` полностью отсутствует (`null`/`undefined`/`''`), с проверкой отсутствия совпадения с именем собеседника прямого диалога.
- 🟩 **Этап 2: Нормализация атрибутов `senderId` в `production/chat/40-messages.js` и мини-чате `production/chat/90-settings.js`**
  - Запись `node.dataset.senderId = m.senderId || m.sender_id || ''`.
  - Приоритетное использование `sId ? ownIds.has(sId) : ...` в логике таймлайна мини-чата.
- 🟩 **Этап 3: Сборка производных ассетов и комплексное тестирование**
  - Запуск `npm run build:preview` для генерации `production/chat.js` и `preview.js`.
  - Запуск `node --test test/test-chat-presentation.mjs`.
  - Запуск визуального теста `node --test test/test-chat-dual-author-separation-visual.mjs` во всех трех темах (`sky`, `dark`, `sand`).
  - Очистка временных файлов и скриптов в рабочей директории.
