## 1. Точная формулировка проблемы и анализ первопричины

- **Проблема 1**: В личной переписке сообщения собеседника отображались на правой стороне экрана с фоном собственных сообщений (`is-own`) и с аватаром текущего пользователя вместо аватара фактического отправителя.
- **Первопричина 1 (Определение принадлежности `isOwnMessage`)**:
  В функции `isOwnMessage` проверка по имени срабатывала даже при несовпадении `senderId`, если у собеседников совпадали имена («Tsovak Palakian»).
- **Проблема 2**: В базе данных Cloudflare D1/SQLite числовые идентификаторы аккаунтов сериализуются как вещественные строки (`"7.0"`, `"8.0"`), в то время как сессия возвращает целочисленный идентификатор (`"7"`). Строгое сравнение `"7.0" === "7"` приводило к сбою определения авторства, потере блока галочек (`(own ? '<span class="msg-receipt">...' : '')`) и невозможности найти фото профиля в словаре `profileViews`.
- **Проблема 3 (Отображение только одной галочки вместо двух)**:
  В серверном модуле `src/chat-durable.mjs` метод `message(row, account)` ищет курсоры участников через `WHERE active=1 AND id<>? AND id<>?` с `acc, memberId`. Так как `acc` передается как `'7'`, а в таблице `members` id равен `'7.0'`, условие `id <> '7'` истинно для `'7.0'`. База включает самого автора в список собеседников с непрочитанным курсором `0`, из-за чего `Math.min(...readValues)` всегда равен 0, и флаги `read` и `delivered` возвращаются как `false`.

## 2. Поэтапный чеклист реализации

- 🟩 **Этап 1: Коррекция логики идентификации авторства `isOwnMessage` в `production/chat/00-core.js`**
  - Восстановление и сохранение инварианта `if (me && String(m?.senderId ?? '') === me) return true;` для соответствия статическим проверкам долговечного чата.
  - Приоритет проверки `senderId`: если `m.senderId` (или `m.sender_id`) передан и не совпадает с `ownIds`, функция гарантированно возвращает `false` без отката к совпадению отображаемых имен.
- 🟩 **Этап 2: Нормализация атрибутов `senderId` в `production/chat/40-messages.js` и мини-чате `production/chat/90-settings.js`**
  - Запись `node.dataset.senderId = m.senderId || m.sender_id || ''`.
  - Приоритетное использование `sId ? ownIds.has(sId) : ...` в логике таймлайна мини-чата.
- 🟩 **Этап 3: Сборка производных ассетов и комплексное тестирование**
  - Запуск `npm run build:preview` для генерации `production/chat.js` и `preview.js`.
  - Запуск `node --test test/test-chat-presentation.mjs`.
  - Запуск визуального теста `node --test test/test-chat-dual-author-separation-visual.mjs` во всех трех темах (`sky`, `dark`, `sand`).
- 🟩 **Этап 4: Нормализация идентификаторов с плавающей точкой (`"7.0"` ↔ `"7"`) и загрузка аватаров собеседника**
  - Поддержка числового эквивалента идентификаторов в `isOwnMessage`, `chatReceiptMarks` и `syncMiniTimeline`: распознавание `"7.0"` как `"7"`, обеспечивающее гарантированное определение исходящих реплик ученика справа с блоком квитанций (`check` / `check-check`).
  - Нормализация идентификатора в `paintProfiles` и `scheduleProfiles`: сопоставление ключей `"8.0"` и `"8"`, обеспечивающее загрузку реального фото учителя в таймлайне вместо инициалов `TP`.
- 🟩 **Этап 5: Нормализация расчетов квитанций (Delivered / Read) в Durable Object `src/chat-durable.mjs`**
  - В `ChatRoom.message(row, account)`: исключение всех строковых и канонических числовых представлений автора (`acc`, `canonical(acc)`, `memberId`, `canonical(memberId)`) из выборки курсоров `cursors`, чтобы курсор рассчитывался строго по собеседникам.
  - В `ChatRoom.member(actor)`: поиск участника по строковому и каноническому числовому ID (`id=? OR id=?`), предотвращающий коллизию участников с одинаковыми именами.
  - В `ChatRoom.read(actor, body)` и `emit`: рассылка уведомлений о прочтении с учетом канонических числовых идентификаторов получателей.
  - Сборка и прогон автоматических тестов с верификацией двойных галочек.
