# TXT-логи CI в Telegram

🟨 Уточнение пользователя: после обычного уведомления отправлять TXT только при failure подготовки/test job, самих тестов или deploy. При success, skipped или cancelled без failure логи не скачивать и не отправлять. Не включать незавершённый notify job и не подменять отсутствующие логи результатами старой попытки.
🟨 Выдать Actions read только notify job, использовать временный GITHUB_TOKEN. Получать логи через GitHub API с ограничением размера; не передавать Authorization по подписанным перенаправлениям.
🟨 Перед отправкой скрыть доступные процессу секреты, значения именованных credentials, Bearer-токены и подписи URL. GitHub также маскирует зарегистрированные secrets; произвольные неразмеченные приватные данные гарантированно распознать невозможно.
🟨 Отправлять multipart TXT напрямую в Telegram, без публичных artifacts и сохранения сырых логов в репозиторий. При недоступности части логов указывать это в файле; при ошибке вложения обычное уведомление сохраняется, job сообщает ошибку.
⬜ Пользователь запускает `npm run check -- --mode=local ci-telegram-logs check-environment`, затем проверяет новый workflow. Агент не читает реальные логи и не отправляет сообщения при реализации.

## Ограничения
Размер каждого ответа ограничен 8 MiB, метаданных — 1 MiB; превышение отражается как недоступный лог со ссылкой на Actions. При принудительной отмене всего workflow GitHub может не выполнить notify job. Локальный post-commit notifier не меняется.

Сообщение коммита: `Attached sanitized CI job logs as a Telegram text file`.
