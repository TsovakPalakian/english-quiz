## 2. Судебно-технический анализ замечаний

### 2.1. Исключение токена сессии из JSON-ответа
* **Текущее состояние в коде**:
  - [speakout/server/server.js:394](file:///Users/tsovakpalakian/PycharmProjects/english-quiz/speakout/server/server.js#L394): ответ `POST /api/speakout/session` возвращает тело `user: { id: requestedId, role, sessionToken: session.token }`.
  - Наличие токена в JSON нивелирует защиту флага `HttpOnly` установленной cookie, так как клиентские сценарии могут прочитать токен из тела ответа и отправлять его через заголовок `Authorization: Bearer`.
* **Требуемое решение**:
  - Удаление поля `sessionToken` из JSON-ответа. Тело ответа возвращает только `{ success: true, authenticated: true, user: { id: requestedId, role } }`. Токен передается исключительно через защищенную cookie `HttpOnly; SameSite=Strict; Path=/; Max-Age=86400`.

---

### 2.2. Транзакционная надежность сохранения сессий в SQLite
* **Текущее состояние в коде**:
  - [speakout/server/server.js:64-71](file:///Users/tsovakpalakian/PycharmProjects/english-quiz/speakout/server/server.js#L64-L71): при сбое записи в таблицу `speakout_sessions` ошибка перехватывается в `catch`, токен все равно помещается в карту оперативной памяти `activeSessionsCache`, и клиенту возвращается `success: true`. После перезапуска процесса сессия теряется.
* **Требуемое решение**:
  - Обеспечение строгой транзакционности: при сбое базы данных SQLite метод `createServerSession` генерирует исключение, клиенту возвращается HTTP 500 (`Database session persist failed`), а несохраненный токен не помещается в память.

---

### 2.3. Исключение отражения локальных IP в политике CORS
* **Текущее состояние в коде**:
  - [speakout/server/server.js:182](file:///Users/tsovakpalakian/PycharmProjects/english-quiz/speakout/server/server.js#L182): `if (/^https?:\/\/(192\.168|10)\.\d+\.\d+(:\d+)?$/.test(origin)) return origin;`
  - Позволяет сторонним страницам в локальной сети выполнять кросс-доменные запросы с чтением ответов сервиса.
* **Требуемое решение**:
  - Удаление автоматического отражения диапазонов `192.168.*` и `10.*` из заголовков CORS. Доступ с планшетов по локальной сети через `http://<IP>:3456/` работает по правилам одного источника (Same-Origin) и не требует ослабления кросс-доменной защиты.
