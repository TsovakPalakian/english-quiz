# Устранение мерцания кнопки Unassigned на странице Groups

## 1. Причина проблемы (Root Cause)
1. При переходе на страницу групп (`show('groups')`) функция `paintGroups()` вызывается синхронно до того, как сетевой запрос `groupPull()` к `/api/groups` завершится.
2. В `paintGroups()` вызывается `groupNormalize()`. Поскольку массив `classGroups` изначально пуст (`[]`), `groupNormalize()` создавал временную заглушку `{ id: "group-default", title: "Group 1", date: lmToday(), hidden: false, lessonIds: [] }`.
3. Название `"Group 1"` не начинается ни с одного стандартного уровня (`A1..C2`), поэтому функция `accountGroupLevel({ title: "Group 1" })` возвращает значение `'unassigned'`.
4. Функция `levelButtons()` видит в списке групп объект с уровнем `'unassigned'` и добавляет кнопку **Unassigned** в список карточек уровней на первом кадре рендеринга.
5. Спустя 50–150 мс запрос `/api/groups` завершается и перезаписывает `classGroups` реальными группами пользователя с сервера.
6. Если у преподавателя/пользователя нет нераспределённых групп (все группы привязаны к уровням A1, A2, B1 и т.д.), `rows.some(row => accountGroupLevel(row) === 'unassigned')` становится `false`, и кнопка **Unassigned** удаляется из DOM.
7. Это приводит к заметному миганию кнопки **Unassigned** при каждом переходе на страницу Groups.

---

## 2. План исправления

- 🟩 **Этап 1: Устранение мерцания кнопки «Unassigned» на странице Groups**
  - 🟩 Исключить добавление фиктивной группы `Group 1` в `groupNormalize()`, если пользователь авторизован (`authUser`) и данные групп ожидаются с сервера (`!classGroupsReady`).
  - 🟩 В `levelButtons()` добавлять категорию `'unassigned'` только при подтверждённой загрузке данных (`classGroupsReady`) при наличии реальных нераспределённых групп.
  - 🟩 Пересобрать `preview.js` (`npm run build:preview`) и продакшен-ассеты (`ops/build-learning-production-assets.mjs`).
  - 🟩 Проверить отсутствие мерцания при переходе на страницу Groups и прогнать полный тестовый набор `ops/check-all.mjs`.
