## B–G. Chats

### Выделение и удаление

- [ ] **C2.** После Select можно выбрать несколько сообщений; Delete должен удалять **все выбранные**, а не только то, на котором снова открыли контекстное меню.

### Медиа: отправка фото

- [ ] **C5.** Выбор/вставка фото: **не** слать сразу. Показать превью + поле комментария; отправка по Enter / кнопке Send. Комментарий — **не** отдельное сообщение: текст под фото в том же bubble (как caption).

### Медиа: запись

- [ ] **C6.** Аудио/видео запись (скрин 3, поведение как в Telegram hold-to-record):
  - удерживают на кнопке → отпустили → отправка как сейчас;
  - потянули в сторону (lock) → запись фиксируется; после отпускания — UI «удалить / отправить»;
  - жест отмены (отпустить вне зоны) сохранить понятным.

### Медиа: только продумать

- [ ] **C7.** Конвертор видео до ≤25 MB — **не делать сейчас**. Варианты (выбрать позже):
  1. **Клиент MediaRecorder + bitrate/resolution cap** перед upload (быстро, качество зависит от браузера; HEVC/Safari отдельно).
  2. **Клиент ffmpeg.wasm** (предсказуемый CRF/scale; тяжелый бандл ~10–30MB, CPU на устройстве).
  3. **Сервер Worker/R2 + внешний encoder** (очередь, стабильный результат; стоимость/latency; нужен лимит и прогресс).
  4. **Два порога:** ≤25MB без перекодирования; больше — предложить сжатие (клиент) или отказ с подсказкой.
  5. **Постер + HLS/chunk** только для длинных (сложнее, не для MVP).
  Рекомендация к обсуждению: (4) + клиентский cap bitrate; ffmpeg.wasm как опция «Compress»; сервер — если появятся жалобы на слабые телефоны.

### Медиа: просмотр и кружки

- [ ] **C8.** Клик по фото: не `target=_blank`. Lightbox поверх чата; чат под ним blur/dim как фон.
- [ ] **C9.** Кружочки и голосовые — UX как в Telegram (playback UI, круговой прогресс / waveform, тап play/pause). Сверить с текущим recording UI.

### Chat info / Files / подписи

- [x] **C10.** После удаления файлов сразу обновлять список Files в info (без перезагрузки комнаты).
- [x] **C11.** «Archived Chats» → **«Archived»**.
- [x] **C12.** В Study Alerts и Contacts: нет Archived и папок — только **Pin**.
- [x] **C16b.** «Chat info» → **«Info»**, заголовок по центру.
- [x] **C17.** В Info клик **Members** должен открывать состав / действие (сейчас noop).
- [x] **C20.** Лупа поиска заметнее. Кнопка панели рядом с лупой — **toggle** Info (открыть и закрыть). Скрин 4.

### Contacts / Personal / Sound / группы в списке

- [ ] **C13.** ПКМ по контакту → Sound: добавить **прослушивание** рингтона перед/при выборе.
- [ ] **C14.** ПКМ на вкладке Personal: действие вернуть чат в **Contacts** (убрать из Personal).
- [ ] **C16a.** Contacts: клик по группе показывает студентов группы **на вкладке Contacts** (не прыгать на Personal). В Info состав уже ок — выровнять поведение.
- [ ] **C18.** Contacts: после отправки сообщения в группу — группа появляется/переходит в **Personal**.
- [ ] **C19.** Создание групп: UI создания; создатель задает ограничения группы; группы вверху списка Contacts.

### Поиск, edit, цвет, pin bar

- [ ] **C21.** Поиск по чату: проверить на тестовых данных. Режимы: точное совпадение; ignore-case / case-sensitive; опционально regex (с безопасным лимитом/ошибкой при невалидном паттерне).
- [ ] **C22.** Edit message: палитра цвета не уходит под модалку (z-index / portal). Скрин 5.
- [ ] **C23.** Закрепы: порядок = порядок закрепления. На закрепленном сообщении — индикатор pin. Клики по верхней панели pin — цикл от последнего к первому.
- [ ] **C24.** Цвет текста из **дополнительной** палитры реально применяется (не только стандартные swatch).
- [ ] **C25.** Edit message как композер: pin, emoji, цвет, звук/видео; отправка кнопкой/иконкой как в чате; кнопку «Edit message» убрать; высота растет с текстом до ~4× текущей.

## J. Invite, auth, видимость

Реализация через **выбор teacher/developer** при создании invite (не отдельный Google-first поток).

- [x] **H5 (часть).** Invite link для группы:
  - teacher/dev в Accounts → группа → **Invite link** выбирает teacher/dev и создает ссылку `/?invite=id.secret`;
  - secret в БД как SHA-256 (`catalog_documents` / `account-invites`); group/teacher только на сервере;
  - студент открывает ссылку → логин/регистрация как сейчас → после входа auto-redeem → назначение в группу;
  - API: `GET/POST /api/accounts/invites` (peek без сессии по `?token=`).
- [ ] **H5 (осталось).** Google OAuth — в коде нет, отдельный этап.
- [ ] **H5 (осталось).** Email OTP / проверка рассылки кода — в коде нет (сейчас password register + teacher approval).
- [ ] **H5 (осталось).** QR/штрихкод для той же ссылки.
- [ ] **H5 (осталось).** Redeem без предварительного Approve (авто-approve по валидному invite при register).
- [x] **H9.** В чате студент видит staff только из assigned teachers своей группы (dev всегда; если assignments пустые — legacy: все ADMIN).
- [x] **H10.** В чате студент видит только свою группу и одногруппников; discover ограничен той же видимостью.
