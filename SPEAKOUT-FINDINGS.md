# Speakout: находки 1–92

Список снят с кода на диске в этом проходе. Правки кода сюда не входят.

## Уязвимости

1. Ключ учебника скачивается ученической сессией без пароля. `GET /api/speakout/document?doc=keys` проверяет только наличие сессии (`speakout/server/server.js:850–855`). `POST /api/speakout/session` с ролью `student` пароль не требует (`server.js:533–540`, `554–557`). Если у `keys` нет пути, берется `documents.teacherResources`, файл `SO3_A1_SB_AK.pdf` целиком (`server.js:868–869`). То же имя `teacherResources` без роли `teacher` или `developer` дает 403 (`server.js:858–862`). Клиент сам создает ученическую сессию (`speakout/web/app.js:712–716`) и открывает ключ с cookie (`app.js:258–260`). Тест ждет 200 для студента (`speakout/tests/security_hardening.test.js:213–227`).

2. `GET /api/speakout/manifest`, `GET /api/speakout/lesson/A1/1A` и `GET /api/speakout/lesson/A1/1D` сессию не спрашивают (`server.js:417–447`, `452–483`, `488–501`).

3. Срезаются только поля `answer`, `answerText` и `answerKeys` (`server.js:291–295`). В ответ 1A остаются `category` (`speakout/data/manifest.json:619`), `contracted` (`manifest.json:653`) и `pairs` (`manifest.json:685–708`). В `lesson1d` остаются `bagA_items`, `bagB_items` (`manifest.json:2014–2022`) и `parts` (`manifest.json:2049–2051`, `2068–2071`).

4. Текст видеоскрипта на маршруте 1D не срезается. `stripVideoscripts` включается только явным `true` (`server.js:278`). Вызов 1D этот флаг не передает (`server.js:496–500`). Объект лежит в `manifest.json:1687`. Манифест флаг передает (`server.js:445`), с `/api/speakout/manifest` тот же текст не уходит.

5. Пять классных mp3 отдаются без сессии (`server.js:758–794`). Список `1.01`, `1.02`, `1.03`, `VB1.01`, `VB1.04` посторонний `track` отсекает (`server.js:761–765`).

6. Два mp4 отдаются без сессии: `SO3 A1 U1 BBC StreetInt.mp4` и `SO3 A1 U1 BBC Vlogs.mp4` (`server.js:798–833`). `..`, `/` и `\` отсекаются (`server.js:803–806`).

7. PDF ученика и PDF видеоскриптов отдаются без сессии. Разрешены `studentBook`, `videoscripts`, `keys`, `teacherResources` (`server.js:841`). Сессия проверяется только у `keys` и `teacherResources` (`server.js:850–863`).

8. Заполнение диска записями. Новая ученическая сессия дает новый `user_id` (`server.js:554`). Лимит — 10 созданий сессии в минуту на IP (`server.js:70–98`). На пару урок/трек пишется до 512 КБ (`server.js:715–717`), пар пять (`server.js:728`). Чужой `userId` из тела не принимается (`server.js:720–724`).

9. Первый `POST /api/speakout/progress` читает учебник целиком в память (`server.js:250–259`, вызов `648`). Если PDF не открылся, потолок молча становится `177` (`server.js:268`).

10. Прямой процесс без `HOST` и без `SPEAKOUT_HOST` слушает `0.0.0.0` (`server.js:946–948`).

11. На стенде ветки `/api/speakout`, `/speakout` и `/speakout/` выходят до проверки хоста (`ops/run-learning-stage.mjs:58–61`). Слушает стенд по умолчанию `127.0.0.1:8788` (`run-learning-stage.mjs:121–122`). Если интерфейс открыт, эти ветки принимают любой заголовок `Host`. Остальные маршруты стенда требуют `Origin` равный `http://127.0.0.1:<порт>` (`run-learning-stage.mjs:63–69`).

12. При `TRUST_PROXY=true` IP для лимита сессий берется из первого значения `X-Forwarded-For` (`server.js:102–105`). Этот hop задает клиент. Без `TRUST_PROXY` заголовок не читается.

13. Флаг `Secure` у cookie ставится только если сокет уже TLS, либо `TRUST_PROXY=true` и `x-forwarded-proto` равен `https`, либо `SECURE_COOKIES=true` (`server.js:564–573`). За HTTPS-прокси без этих условий cookie уходит без `Secure`. Подделка `x-forwarded-proto` без `TRUST_PROXY` флаг не включает.

14. `POST /api/speakout/session` не смотрит `Origin` (`server.js:518–584`). `SameSite=Strict` не отделяет поддомен `lumiscia.org`. CORS отражает `https://<поддомен>.lumiscia.org` (`server.js:236–237`). Заголовка `Access-Control-Allow-Credentials` нет. Тело `{}` создает ученическую сессию и заменяет учительскую, потому что роли не совпали (`server.js:543–552`).

15. Граница каталога считается через `path.resolve`, не через `realpath` (`server.js:165–168`). Поток идет по этому пути (`server.js:787–794`, `819–833`, `879–886`). Симлинк внутри каталога курса, указывающий наружу, проходит проверку.

16. После превышения лимита сокет не закрывается. Запись речи перестает копить тело после 524288 байт и читает остаток (`server.js:687–693`). Прогресс делает то же после 8192 байт (`server.js:611–616`). У сессии при 100000 байт вызывается `req.destroy()` (`server.js:528`).

17. `activeSessionsCache` не имеет потолка (`server.js:60`, `128`). Срок токена 86400 секунд (`server.js:110`). Просроченные строки удаляются только в момент создания новой сессии (`server.js:122`).

18. Прямой сервер не ставит `Content-Security-Policy`, `X-Content-Type-Options` и `Referrer-Policy` (`server.js:400–408`). Стенд эти заголовки ставит до ветки speakout (`run-learning-stage.mjs:49–53`).

19. Ответ 416 возвращает клиенту присланный заголовок `Range` (`server.js:356`).

20. `speakout/data/speakout.db` создается без явного режима файла (`server.js:20–21`). В файле лежат токены сессий (`server.js:23–28`) и `audio_base64` (`server.js:38–45`).

21. Пароль учителя не зашит в файл. Сравнение идет через SHA-256 и `timingSafeEqual` (`server.js:63–67`, `532–540`). Отдельного лимита на неверный пароль нет: действует общий лимит 10 сессий в минуту. Запрос роли `developer` при верном пароле сохраняется как `teacher` (`server.js:540`). Пустой `SPEAKOUT_TEACHER_PASSWORD` учительскую роль не выдает (`server.js:535`).

22. Cookie `learning_stage` принимается только если значение уже есть в `speakout_sessions` (`server.js:207–210`). Стенд выдает свой `learning_stage` (`run-learning-stage.mjs:85`), и этот токен в таблице speakout не лежит. Действующий токен speakout, положенный в cookie с именем `learning_stage`, открывает ту же сессию.

23. `decodeURIComponent` в разборе cookie не пойман (`server.js:177`, вызов `184`). Битая cookie с `%` бросает исключение. На прямом сервере `handleRequest` его не ловит.

24. Плохой заголовок `Host` роняет `new URL` в начале `handleRequest` (`server.js:401`). Исключение не поймано. Это любой маршрут, не только сессия.

25. У ответа с ключом и у прогресса нет `Cache-Control` и `Vary`. Общий кэш может сохранить PDF ключа и отдать его следующему запросу без cookie (`server.js:364–386`, `603`, `886`). На стенде `Cache-Control: no-store` ставится раньше и сохраняется.

26. `POST /api/speakout/progress` и `POST /api/speakout/speech/record` не проверяют `Origin` и `Content-Type` (`server.js:608–626`, `684–702`). Страница того же сайта может послать `text/plain` с JSON. Cookie уйдет, запись в базу произойдет, ответ браузер спрячет.

27. При 500 ключах карта лимита удаляет самый старый IP и тем сбрасывает его счетчик (`server.js:88–90`).

28. `getStudentBookTotalPages` не запирается. Параллельные первые запросы каждый читают учебник в память (`server.js:250–262`).

29. Сессию нельзя отозвать. Есть только `GET` и `POST /api/speakout/session` (`server.js:506–586`). Токен живет до `expires_at`.

30. `speakout.db` нет в `.gitignore`. В списке есть `accounts.sqlite` (`.gitignore:1`), файла speakout там нет. Токены и записи можно закоммитить.

31. `speakout/data/manifest.json` на диске хранит абсолютные пути домашнего каталога и `answerKeys` уроков, которые три HTTP-маршрута не отдают. Статика отдает только `speakout/web` (`server.js:897–903`). Файл не в `private/` и не в `.gitignore`.

32. Отказной CORS возвращает строку `null` (`server.js:239`). Для браузера это origin песочницы. Любой сайт в sandboxed iframe читает публичные JSON и PDF.

33. Отражается любой порт `localhost` и `127.0.0.1` (`server.js:233–234`). Страница на другом порту этой машины читает публичные ответы.

34. У `GET` аудио, видео, документов и манифеста нет лимита частоты (`server.js:417`, `758`, `799`, `838`). Лимит есть только у создания сессии.

35. Каждый такой запрос, включая `Range`, заново читает и разбирает весь `manifest.json` (`server.js:242–245`, вызовы `768`, `817`, `866`).

36. Нулевой байт в пути попадает в `fs.existsSync` без перехвата (`server.js:909`). Исключение выходит из `handleRequest`.

37. Проверка пароля учителя обрывается до `timingSafeEqual`, если пароль в окружении пуст или поле пустое (`server.js:535`). Ответ быстрее, и по времени видно, задан ли `SPEAKOUT_TEACHER_PASSWORD`.

38. Ошибка потока пишется в лог вместе с путем файла (`server.js:374`, `390`). Ошибка сессии в базе тоже пишется (`server.js:159`).

39. Cookie ставится с `Path=/` (`server.js:573`). На общем хосте `speakout_session` уходит на все маршруты этого хоста.

40. Манифест, уроки 1A и 1D, аудио, видео, документ и статика не смотрят метод (`server.js:417`, `452`, `488`, `759`, `799`, `838`, `897–932`). `POST` отдает те же байты, что и `GET`.

41. Проверка `existsSync` и следующий `createReadStream` не атомарны (`server.js:781` и `794`, `827` и `833`, `872` и `886`, `909` и `926`). Между ними файл можно подменить.

42. При `window.__OFFLINE_SPEECH_ENGINE__` и `navigator.onLine === false` страница запускает браузерный `SpeechRecognition` (`app.js:453–486`, `631–632`). В Chrome это уводит речь в сеть. Страница сама флаг не ставит.

43. Сессия принимается из `Authorization: Bearer` и из `x-session-token` (`server.js:193–204`). Прокси часто пишут эти заголовки в журнал доступа.

44. У `POST` прогресса и записи речи нет лимита частоты (`server.js:608`, `684`). Размер тела ограничен, число запросов нет.

45. В схеме `user_id` по умолчанию `student_default` (`server.js:31`, `40`). Текущие `INSERT` передают `user_id`. Вставка без колонки склеит строки в одного пользователя.

46. В коде зашит домашний путь `/Users/tsovakpalakian/Education/English/Speakout 3rd Edition (2022)/Speakout 3rd Edition A1` (`server.js:14`).

47. В JSON ошибки возвращаются присланные `trackId` и `videoFile` (`server.js:764`, `829`).

## Ошибки поведения

48. При старте сохраненная страница читается и сразу затирается. `loadProgress` ставит `currentPage`, затем `loadMainDocument('studentBook', 1)` вызывает `renderPage(1)` и `saveProgress` пишет страницу 1 (`app.js:1000–1003`, `181–183`).

49. Смена урока всегда открывает страницу 1 и не читает сохраненную страницу этого урока (`app.js:801`, `810`).

50. Очистка поля страницы сразу открывает страницу 1 (`app.js:831–834`). Номер нельзя стереть и набрать заново, не прыгнув на первую.

51. `saveProgress` не смотрит код ответа (`app.js:773–786`). `400` и `401` выглядят как успех.

52. Если создание сессии упало, бейдж показывает `student_session`, хотя серверной сессии нет (`app.js:723–729`).

53. Подпись длины в доке зашита как `1:42` (`speakout/web/index.html:137`). Это не длина файла. Она меняется только после `timeupdate`.

54. Подпись масштаба в HTML — `100%` (`index.html:104`), а `state.zoomScale` равен `1.2` (`app.js:42`). Совпадение появляется только после успешного `renderPage`. Если PDF не открылся, подпись остается `100%`.

55. У панели урока D нет паузы, шкалы, скорости и кнопки записи. Они лежат внутри скрываемой панели A (`index.html:131–146` и `150–176`). Трек `VB1.04` с панели D запустить можно, остановить видимой кнопкой нельзя.

56. Кнопки видео не снимают `active` друг с друга. `selectVideo` класс не трогает (`app.js:362–379`). Street Interviews остается помеченным (`index.html:153`).

57. После записи `audioPlayer.onended` не снимается при смене трека (`app.js:662`). `selectTrack` его не чистит (`app.js:352–358`). Конец следующего трека снова запускает прошлую запись ученика.

58. Если у элемента Pearson нет `src` или `play()` отклонен, играется только запись ученика (`app.js:673–677`). Фаза образцового трека пропускается.

59. Смена урока не сбрасывает `activeTrack` (`app.js:790–810`). После `VB1.04` подсветка `1.01` уже снята, а кнопка `VB1.04` спрятана вместе с панелью D.

60. Два перекрывающихся `loadMainDocument` не имеют номера запроса (`app.js:128–162`). Поздний ответ более раннего вызова может показать не тот документ.

61. Подпись ключа «of 36» и страницы 2–5 заданы константами, не `keysPdfDoc.numPages` (`app.js:246–248`).

62. Фраза сверки до выбора трека берется из `TRACK_MODEL_PHRASES` (`app.js:28–34`). У трека `1.01` в манифесте заголовок `Lesson 1A Exercise 1A & 1B` (`manifest.json:32`). `loadManifestData` ищет `transcript` (`app.js:744–748`), а сервер это поле срезает, поэтому ветка не срабатывает.

63. `URL.createObjectURL` для записи ученика не освобождается при новой записи (`app.js:611`).

64. Если подсчет страниц учебника не удался, в кэш пишется `177` и повторной попытки нет (`server.js:265–269`).

65. Номера страниц урока в манифесте клиент не читает. Оба урока открывают учебник со страницы 1. Экран и JSON расходятся.

66. Пока PDF не открыт, клиент показывает 177 страниц учебника и запас 3 для видеоскрипта (`app.js:40`, `145`, `148`, `index.html:87–88`). При ошибке открытия запас остается.

67. Если `MediaRecorder.start` бросает исключение, дорожки `getUserMedia` не останавливаются (`app.js:604–637`).

68. У `<audio>` нет слушателя `ended`. Кнопка остается «пауза», хотя ролик уже кончился (`app.js:382–395`). У видео такой слушатель есть (`app.js:927–930`). Повторное нажатие снова запускает звук, потому что `togglePlayPause` смотрит `paused`, а не `isPlaying`.

69. Смена урока не ставит на паузу ни аудио, ни видео (`app.js:790–810`). Звук урока A продолжает играть на экране урока D, где кнопка паузы скрыта.

70. Быстрый листатель страниц не отменяет уже начатый `getPage`. `cancel` вызывается только у уже созданного `renderTask` (`app.js:194–208`). Более ранний кадр может закрасить холст после более позднего.

71. `saveProgress` не ждет ответ и не нумерует запросы (`app.js:181–183`, `773–782`). Сервер пишет ту страницу, чей `POST` пришел последним (`server.js:665–672`). Более старый запрос может затереть более новую страницу.

72. Запись ученика всегда упаковывается как `audio/webm` (`app.js:610`). Если `MediaRecorder` отдал другой тип, воспроизведение этого blob может не начаться.

73. Кнопка прослушивания ученика и двухфазный повтор каждый раз делают `new Audio()` и не останавливают предыдущий ролик (`app.js:665`, `975`). Два нажатия играют поверх друг друга.

74. `loadMainDocument` подменяет `pdfDoc` и `scriptsPdfDoc` и не вызывает `destroy()` (`app.js:143–148`). Предыдущий документ PDF.js остается в памяти.

75. Если запасной блок PDF уже показан, `selectVideo` его не прячет (`app.js:224–225`, `369–373`). Карточка ошибки остается на экране вместе с видео.

76. Процент `Accuracy` считает слово совпавшим, если оно встретилось где угодно в распознанном тексте (`app.js:532–545`). Одно произнесенное слово поднимает счет всем таким же словам фразы. Лишние слова счет не снижают.

77. Учительский вход с экрана невозможен. Надпись `Teacher Resources (Restricted)` не кнопка (`index.html:74–76`). Клиент всегда шлет `{ "role": "student" }` (`app.js:715`). Поля пароля нет.

78. Ошибки `SpeechRecognition`, кроме `network`, только пишутся в консоль (`app.js:476–483`). На экране они не появляются.

79. Любая ошибка внутри `POST /api/speakout/progress`, включая сбой SQLite, отвечает текстом `Invalid JSON payload` (`server.js:675–677`).

80. `renderPage` меняет `currentPage` и подпись масштаба, но не поле номера (`app.js:165–179`). После смены урока или открытия видеоскрипта в поле остается старый номер, а на экране уже другая страница.

81. `sendSpeechRecording` не смотрит код ответа (`app.js:694–697`). `401`, `400` и `413` не пишут ошибку на экран. Подпись `Saved to speakout.db` появляется только при `success`.

82. В запись уходят `lessonId` и `trackId` на момент отправки, не на момент старта (`app.js:689–690`). Смена урока во время записи кладет ролик в другой урок.

83. Если `POST /api/speakout/session` вернул `429` или `403`, клиент не показывает ошибку и не ставит пользователя (`app.js:712–721`). На бейдже остается текст `Student` из HTML.

84. Ошибка `play()` у трека пишется только в консоль (`app.js:358`). Кнопка образцового ролика в студии запускает звук и не обновляет `isPlaying` (`app.js:966–970`). Иконка дока может показывать «пуск», пока звук уже идет.

85. Если ключ не открылся, модальное окно остается пустым. Сообщение есть только в консоли (`app.js:292–293`).

86. Стенд отдает пути `/speakout` и `/speakout/` в `handleRequest` (`ops/run-learning-stage.mjs:58–61`). Раздача статики срезает только начальный `/` или `/static/` (`server.js:898`). Файл ищется как `speakout/web/speakout/index.html`, а страница лежит в `speakout/web/index.html`. На стенде экран, `app.js`, `style.css` и worker PDF дают 404. API `/api/speakout` при этом отвечает. Прямой сервер с корня `/` страницу отдает.

87. Если правая страница ключа не рисуется, левая уже заменена, а правый холст остается от прошлого урока (`app.js:266–293`). `closeKeysModal` рисование не отменяет (`app.js:297–300`).

88. Закрытие студии во время записи вызывает остановку (`app.js:437–438`). Обработчик `onstop` после этого все равно запускает двухфазный повтор (`app.js:609–625`, `652`). Звук играет при уже закрытом окне.

89. Списки лимита записи и медиа не чистятся. `checkWindowLimit` хранит адрес, пока карта не достигнет 500 ключей, и старые адреса не удаляет (`speakout/server/server.js:100–111`). После 500 разных IP новый адрес получает отказ навсегда, даже когда минутное окно уже пустое.
